# fatcorn753-design — 静か + 温かい

道具として静かで、触ると少し温かい画面にする。
装飾で個性を出さず、余白・文字・色の抑制と、要所の小さな動きで個性を出す。

## 最初にやること

1. 既存プロジェクトなら、独自のトークンやテーマがないか確かめる。あればそちらを優先し、この Skill は UX と文言の規則だけ使う。
2. `assets/` の 3 ファイルをプロジェクトにコピーし、この順で読み込む: `tokens.css` → `base.css` → `components.css`。
   - コピーしたファイルは編集しない。調整はプロジェクト側の CSS で、トークンの上書きとして行う。
3. ルート要素に属性を付ける: `<html lang="ja" data-accent="koke">`。
   - `lang="ja"` は必須(付けないと Android などで中国語の字形になる)。
   - アクセント色は苔(`koke`)を使う。琥珀(`kohaku`)はユーザーが指定したときだけ使う。
   - ライト/ダークは端末設定に従う。切り替え UI を付けるときだけ `data-theme="light|dark"` を使う。
   - 業務ツールの一覧は `data-density="compact"`、読む画面は `"spacious"`。
4. 部品を作る前に `references/components.md` を読む。ある部品はそこに書いてあるマークアップで作る。
5. 作り終えたら「完了前の確認」をすべて行う。

## 絶対の規則

1. **色・余白・角丸・影・時間は、トークン(`var(--…)`)だけを使う。** 16 進数・`rgb()`・`oklch()`・`white`・`black` をコンポーネントに書かない。足りない値は `tokens.css` の仕組みに沿ってプロジェクト側で足す。
2. **背景を変えたら文字色も対で決める。** 地 `--accent-solid` には文字 `--on-accent`、地 `--*-tint` には文字 `--*-text` か `--text-primary`。
3. **ライトとダークの両方で確かめる。** 片方だけで作り終えない。
4. **状態は色だけで伝えない。** 成功・注意・エラーには必ずアイコンか文言を添える。
5. **主ボタンは 1 画面に 1 つ。** 主ボタン以外は無印か ghost にする。
6. **元に戻せる操作は確認せずに実行し、Undo を出す。** 確認ダイアログは、取り返しのつかない操作と外部へ送る操作だけにする。
7. **弾む動き(`--ease-spring`)は、完了チェック・スイッチ・項目の追加・トーストの進入だけに使う。** 色と opacity には使わない。ほかの動きは `--ease-standard` で、`--dur-slow`(320ms)以内にする。
8. **キーボードで全部操作できるようにする。** フォーカスの輪郭は消さない(`base.css` が `:focus-visible` で出す)。
9. **タッチ端末の当たり判定は 44px 以上にする。** 見た目が小さい部品も padding で広げる。
10. **左揃えを基本にする。** 中央揃えは空状態と完了画面だけにする。

## 色の使い方

| 役割 | トークン | 使う場所 |
|---|---|---|
| 画面の地 | `--bg-canvas` | `body` |
| 面 | `--bg-surface` | カード・入力欄・パネル |
| 控えめな面 | `--bg-subtle` | サイドバー・hover・表の見出し・skeleton |
| 浮く面 | `--bg-elevated` | メニュー・ダイアログ・ポップオーバー |
| 区切り線 | `--border-subtle` | 操作できない境界・一覧の行間 |
| 操作部品の枠 | `--border-control` | 入力欄・チェックボックス(背景と 3:1 以上) |
| 本文 | `--text-primary` | |
| 補助 | `--text-secondary` | ラベルの補足・日時・placeholder |
| 主役の地 | `--accent-solid` / `--accent-hover` | 主ボタン・チェック済み・スイッチ ON |
| 主役の文字 | `--accent-text` | リンク・選択中のアイコン |
| 選択中の地 | `--accent-tint` | 選択中の行・`::selection` |
| 状態 | `--success-*` `--warning-*` `--error-*`(`-text` と `-tint`) | バッジ・お知らせ・エラー文 |

- 主役の色を塗る面積は、画面の 1 割以下にする。大きな面を主役の色で塗らない。
- ダークでは影がほぼ見えないため、奥行きは面の明るさの段差で出す: canvas < surface < subtle < elevated。
- 影は `--shadow-sm`(カード)と `--shadow-md`(浮く面)の 2 つだけにする。
- 色を新しく足すときは OKLCH で、同じ明度 L の段階に合わせる。文字は 4.5:1、部品の枠と図形は 3:1 以上を両テーマで満たす。

## 余白・密度・形

- 余白は `--space-*`(4px 基準)だけを使う。兄弟要素の間は margin ではなく、flex か grid の `gap` で空ける。
- 部品の高さは `--control-h`、一覧の行は `--row-h` を使う。どちらも密度の設定とタッチ端末に応じて変わる。
- まとまりの内側の余白は外側より狭くする(近いものほど近くに置く)。
- **形は「葉」にする。** ボタン・入力欄・お知らせ・トーストは `--shape-control`(左上と右下 10px、ほか 3px)、カード・ダイアログ・表の枠は `--shape-panel`(16px / 4px)。この Skill の顔なので、普通の角丸に戻さない。自作の部品で同じ役割のものも、この 2 つを使う。
- 小さいもの(バッジ・チェックボックス・メニュー・切り替え)は `--radius-sm` / `--radius-md` の普通の角丸、スイッチとアバターだけ `--radius-full`。葉の形を小さい部品にまで付けると、うるさくなる。

## 文字

- 書体は `--font-sans`(端末の標準書体)だけを使う。Web フォントを読み込まない。
- 文字の大きさは `--text-xs` 〜 `--text-3xl`(12 / 14 / 16 / 18 / 20 / 24 / 32px)だけを使う。本文は `--text-body`(既定 16px、compact で 14px)にする。
- 太さは 400 / 500 / 600 の 3 つだけを使う。和文の 700 は重すぎる。
- 見出しは 1 画面に 3 段階までにする。大きさの差より、太さと余白で階層を作る。
- 数字の桁をそろえる場所(表・金額・時刻・回数)には `.num` を付けるか `<time>` / `<td>` を使う。`tabular-nums` が効く。
- **集計の数字は `.td-stat` で見せる。** 等幅の数字に小さな単位を添え、下に日ごとの刻み(`.td-ticks`、濃さ 0〜3)を並べる。時間は「3:25」のように書く。刻みは飾りなので `aria-hidden` にし、意味は数字と文で伝える。巨大な数字のタイルにはしない。
- 読む文章の 1 行は `--measure`(38em)以内にする。

## 動き

| 時間 | 使う場所 |
|---|---|
| `--dur-instant` 80ms | hover・押下・色の変化 |
| `--dur-fast` 150ms | トグル・ドロップダウン・退出 |
| `--dur-base` 220ms | タブ切替・展開・トーストの進入 |
| `--dur-slow` 320ms | ダイアログ・シートの進入 |
| `--dur-spring` 340ms + `--ease-spring` | 完了チェック・スイッチ・項目の追加 |
| 芽吹き 約 1 秒 | やることを完了にした瞬間だけ(`data-sprout`) |

- 退出は進入より短くする。
- 移動の距離は `--motion-enter-y`、拡大の起点は `--motion-pop-from`、押下の縮小は `--motion-press` を使う。どれも「視差効果を減らす」設定で自動的に無効になり、フェードだけが残る。独自の動きを足すときも、距離と拡大率は同じようにトークンにする。
- `transition: all` を使わない。変える性質だけを列挙する。
- 繰り返し続ける装飾の動き、パララックス、スクロールで発火する演出は使わない。
- **完了の演出は「芽吹き」1 つだけ。** やること(`data-strike` の付いたチェック)を完了にした瞬間、チェックの上に芽が出て消える。付け方は references/components.md。設定の保存・送信などほかの完了には使わない。

## UX の規則

- **待ち時間**: 100ms 以内に何かが反応するようにする。300ms 未満の処理には読み込み表示を出さない。画面の形が分かっていれば skeleton、局所の処理なら spinner。10 秒を超えそうなら進み具合とキャンセルを出す。
- **保存**: 可能なら自動保存にし、「保存しました」「保存中」の状態を常に見えるところに出す。
- **入力**: 検証はフォーカスが外れたときか送信時に行う。送信ボタンを disabled にしない。エラーは欄の真下に出す。
- **削除**: 1 件の削除やアーカイブは即実行し、トーストで Undo を出す。Undo 付きのトーストは自動で消さない。
- **選択肢**: 1 画面の選択肢は少なくし、二次的な操作は「…」メニューや詳細画面に移す。
- **記録の入力**: 1 タップで記録でき、詳細はあとから足せるようにする。
- **ショートカット**: 業務ツールでは、よく使う操作にキーボードショートカットを付ける(検索は `/` か `Ctrl/Cmd+K`)。
- **固定バー**: 固定ヘッダーやフッターがあるときは `scroll-padding` を合わせ、フォーカスが隠れないようにする。
- **モバイル**: 主な操作は画面の下半分に置く。safe-area を考える。

## 文言

- 説明・エラー・空状態・確認は敬体(です・ます)で、動詞まで言い切る。
- 見出し・ラベル・ステータス・バッジは体言止めにする(「保存済み」「同期中」「下書き」)。
- ボタン: 通常の操作は短く(「保存」「追加」「閉じる」)。取り返しのつかない操作は対象と動詞を明示する(「この記録を削除する」)。「OK」「はい」を使わない。
- エラーは「何が起きたか」と「どう直すか」を書く。ユーザーを責めない。内部のエラーコードだけを見せない。
  - 悪い例: 「入力値が不正です」
  - 良い例: 「開始日は終了日より前の日付を選んでください。」
- 感嘆符、過剰な敬語(「〜くださいませ」)、「〜することができます」を使わない。
- 仕組みの言葉ではなく、使う人の言葉で書く(「Webhook 設定」ではなく「通知の送り先」)。

## 禁止事項(AI っぽい見た目)

- 紫〜青のグラデーション、光るぼかし、文字のグラデーション(`background-clip: text`)
- 装飾目的の `linear-gradient` / `radial-gradient`
- 絵文字を UI のアイコンや見出しの印に使うこと
- 何でも中央揃え
- 何でもカードにすること、カードの入れ子、均等な 3 列の機能カード
- カード左端の太い色線(`border-left: 3px` 以上)
- 目的のない `backdrop-filter`(すりガラス)と濃い影
- 画面の高さいっぱいの巨大なヒーロー、巨大な数字のタイルを並べた冒頭
- 飾りのピル型バッジ、意味のない番号付け(01 / 02 / 03)
- 複数回揺れるバウンス、ホバーで浮き上がるカード
- クリーム色の地 + テラコッタ、黒地 + 蛍光色ひとつ
- 色付きの面に薄いグレーの文字
- ダミー文(lorem ipsum)。実際に使われそうな文言で作る

## Tailwind を使うプロジェクト

`tokens.css` を読み込み、`@theme inline` でトークンを Tailwind の名前に対応させる。Tailwind の既定の色(`slate-*` `white` など)は使わない。

```css
@import "tailwindcss";
@import "./tokens.css";
@import "./base.css";
@theme inline {
  --color-canvas: var(--bg-canvas);
  --color-surface: var(--bg-surface);
  --color-subtle: var(--bg-subtle);
  --color-elevated: var(--bg-elevated);
  --color-line: var(--border-subtle);
  --color-control: var(--border-control);
  --color-fg: var(--text-primary);
  --color-fg-muted: var(--text-secondary);
  --color-accent: var(--accent-solid);
  --color-accent-hover: var(--accent-hover);
  --color-accent-fg: var(--accent-text);
  --color-accent-tint: var(--accent-tint);
  --color-on-accent: var(--on-accent);
  --radius-sm: var(--radius-sm);
  --radius-md: var(--radius-md);
  --radius-lg: var(--radius-lg);
  --radius-control: var(--shape-control); /* rounded-control。葉の形 */
  --radius-panel: var(--shape-panel);     /* rounded-panel */
  --font-sans: var(--font-sans);
}
```

## 完了前の確認

1. 検査スクリプトを実行し、指摘を直す。`assets/` からコピーした 3 ファイルは自動で除外される。

   ```bash
   python3 ~/.claude/skills/fatcorn753-design/scripts/check_design.py <対象のディレクトリかファイル>
   ```

2. ブラウザで次をすべて確かめる。確かめられなかった項目は、完了報告に「未確認」と書く。
   - ライトとダーク(`data-theme` を切り替える)
   - 幅 375px で横スクロールが出ない
   - Tab キーだけで操作でき、フォーカスが見える
   - 「視差効果を減らす」を有効にしても、状態の変化が分かる
   - 空・読み込み中・エラー・大量データ(長い文字列を含む)の各状態
3. 新しい色の組み合わせを足したときは、コントラスト比を計算して確かめる。
